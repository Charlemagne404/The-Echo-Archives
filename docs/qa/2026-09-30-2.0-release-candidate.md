This was local loopback evidence, not a deployment to the configured external staging host. It does not prove cross-origin production isolation or operator deployment behavior for a clean candidate SHA.

The checked-in private-host release contract was inspected. `./deploy/echo staging <commit>` fetches/builds the specified SHA, deploys only to the isolated staging pointer/runtime/database, and runs staging health plus smoke checks; on failure it restores the previous staging release and does not touch production. The separate `./deploy/echo deploy <commit>` fast path automatically promotes a passing staged artifact to production, so it is not a staging-only command. Neither remote command was run: this worktree has no clean candidate SHA, and the host-side deployment configuration and availability have not been confirmed. Once a candidate commit is available to the deployment host, the stage-only command is the appropriate documented path.
